## 一、产品版图:一条"独立 UEBA → 并入 SIEM"的演进线

| | Splunk UBA(老产品) | ES 内置 UEBA(新一代) | Behavioral Analytics Service |
|---|---|---|---|
| 形态 | 独立专用服务器 + Add-on 与 ES 双向同步 | ES 8.x Premier 版内置(内容应用 + 风险引擎) | Splunk Cloud 侧托管行为检测服务 |
| 机制 | 自带 ML 管道、peer group 画像、专用异常库 | 统计偏差检测 + Risk Data Model + 实体风险分 | 云端检测,结果落 ES Content Management |
| 检测 | 批/流/威胁模型约 70+ 模型、60+ 异常规则 | 云端 176 条 / 本地 119 条(几乎两套独立内容) | 22 个 Windows 事件 ID 驱动的行为检测 |
| 现状 | **End-of-Sale 2025-12-12,End-of-Support 2027-01-31**,文档已挂 EOL 横幅 | 现行主推,官方明确为 UBA 继任者 | 云版新增能力,默认写 `ba_test` 沙箱索引 |

关键结论:Splunk 已经放弃"旁挂式独立 UEBA 设备"路线,把行为分析做成了 **SIEM 风险评分引擎上的一类检测内容**(findings 直接进 Risk Data Model,复用 RBA 的实体评分与调查界面)。检测内容云端与本地目前是两套,官方称后续会归一。

## 二、核心机制速查

### 1. 检测运行与灰度(findings 流水线)
- 检测产出 **finding / intermediate finding**(ES 8.0+ 术语,分别取代 notable/risk event),字段含实体、MITRE tactic/technique、confidence、impact、threat objects、risk_score,写入 `risk` 索引。
- 云端默认写 **`ba_test` 沙箱索引**(不污染生产风险分),验证后再 "Turn on in risk index";三态开关:in risk / in test / off。
- 检测**只读**(不可改 SPL),调优手段只有 finding exclusion;检测需最长 **30 天**学习基线才产出异常。

### 2. 实体风险分(ERS)
- 过去 7 天窗口,归一化 0–100,计划搜索每 20 分钟计算,存 `ers` 索引。
- 5 组件加权平均:①全部中间发现分数总和 ②单条最大分 ③分数≥50 的发现数 ④发现总数 ⑤跨检测求和(每检测只取最高分,防单规则刷分)。
- 分数可解释:仪表盘可 Show calculation、按 ATT&CK tactic 拆解;徽章 4 档配色。

### 3. 风险因子与修饰
- 事件分公式:`(base_score + Σ加法因子) × Π乘法因子`,加法先于乘法;因子存 `risk_factors.conf`,免写搜索。
- 内置 7 个默认因子(默认关闭):Admin user ×1.5、Watchlisted user ×1.5、High priority user ×1.25、Contractor +5、Critical destination ×1.5 等。
- 风险修饰支持 threat object(domain、file_hash 等)→ 驱动威胁拓扑图(≤20 实体,按共享 threat object 连边)。

### 4. 降噪与治理
- **Entity lists**(≤500 条):静态实体分组,条件三选一(Source/Category/对 normalized_risk_object 做 pattern match),同时服务仪表盘过滤与 finding exclusion 条件。
- **Finding exclusions**(≤2000 条):从 Risk Data Model 移除 intermediate findings;规则绑定单一检测、Reason 三选一(Remediated/Accepted/Detection accuracy)、可设到期日、有预览、30 分钟生效。

### 5. 仪表盘全景(Analytics > UEBA,数据来自 index=risk,延迟约 30 分钟)
UEBA overview(全局风险+实体排行)→ Entity analysis(7 天风险趋势、关联实体、检测热力图、基线可视化、时间回溯)→ Entity risk score(按因子与 tactic 拆解)→ Entity detection activity → All related investigations(Mission Control);另有审计 Diagnostics(管道健康 + ERS 正确性)。

### 6. 服务限制
云端 45k–60k EPS、唯一用户/设备各 ≤300 万;Entity lists ≤500、Finding exclusions ≤2000(云端/本地一致)。

## 三、检测内容概貌(详见分册 01)

- **云端 176 条**:Windows 端点威胁/LOLBAS(76)、认证与登录异常(38)、云存储与文件(24)、账号权限(13)、Okta/O365/Box(11)、邮件(8)、VPN 位置(6);大量使用 **Activity Model 基线模型**。
- **本地 119 条**:网络流量传输异常(34)、认证登录(34)、打印(24)、USB(8)、邮件与 DLP(7)、账号与日志篡改(5)、HTTP 代理(4)、主机失陷关联(3);是 **CIM 数据模型上的统计偏差规则**,按 per User/Device × by Company/Business Unit 维度组合展开。
- 两边同名共有仅 12 条。
- **必需 sourcetype**:云端 8 组(Windows 事件日志、O365、Infoblox DHCP、Box、Cisco ASA、Okta、Palo Alto GlobalProtect);本地 11 组对齐 6 个 CIM 模型(Authentication/Network_Traffic/Web/Change/Endpoint/Email),其中 Symantec EP 文件行为是唯一标记"必需"的。

## 四、老产品 UBA 的可借鉴模型体系(详见分册 03)

- 模型四类:Batch(24h 夜间批)、Streaming(实时短窗)、Security analytics、Threat models;威胁计算 4 种:Kill-chain / Graph-based / Data-driven(内部威胁)/ Rule-based。
- 7 大用例:Account Misuse、失陷账号、失陷机器、上下文情报、数据外泄、横向移动、未知威胁。
- ML 机制:无监督学习 + 4 种 peer group(HR/OU/行为聚类/设备)画像;数百万事件 → 数百异常 → 少量威胁的漏斗;False Positive Suppression 深度学习自动抑制误报;模型参数经 ModelRegistry.json 可调。

## 五、对我们自研 UEBA(Zeek 流量 + 用户行为日志,防泄密场景)的启示

1. **"Rare X by Y" 稀有值检测模式**是本地版主力范式(罕见目标/罕见时间/罕见协议 × 罕见用户/设备),纯统计、免训练、可解释,可直接套在 Zeek conn/ssl/dns/http 日志上。
2. **维度展开法**:同一基线逻辑按 per-User/Device × by-Company/Business-Unit 组合展开成检测矩阵,即"个体基线 + 群体基线"双视角,替代 Splunk UBA 的 peer group。
3. **两层评分架构**:事件分(intermediate finding,带 MITRE 标注)→ 实体分(ERS,多组件防刷分),实体分反哺新检测(`ers>=80` 触发),形成"检测→评分→更强检测"的飞轮。
4. **沙箱灰度**:检测先在影子索引/影子评分里试跑 30 天基线,确认误报率后再进生产——对应我们的"检测上线流程"设计。
5. **排除规则即治理**:排除必须绑定检测、写明原因分类、带到期日、可预览命中,避免运维悄悄"关规则"导致能力退化。
6. **实体 schema 先行**:Splunk 明确声明必需字段(身份/资产的 priority、category、watchlist、business unit)并做数据质量诊断——实体数据质量是 UEBA 落地第一道坎。
7. **检测清单对标**:本地版"网络流量传输异常 34 条 + HTTP 代理 4 条"与我们 Zeek 预研清单直接对标,可逐条对照查漏;UBA 的 7 大用例可作为我们场景分类的顶层框架。
