## 2. 对既有预研材料的关键修正

原有 00～08 分册作为历史笔记保留。以下修正适用于最终汇报，避免在引用旧笔记时延续不准确概括。

| 旧说法或易产生的理解 | 最终报告的正确口径 | 依据 |
|---|---|---|
| 独立 UBA 风险引擎被 ES 完整继承，两代共享相同评分骨架 | 官方公告证明投入转向 ES Premier；不证明算法、状态及架构完整继承 | S07、S12、S16 |
| Splunk 放弃了独立行为引擎，所以自研也应并入 SIEM | 产品停售是事实，自研边界取决于我们的需求及成本 | S07；工程分析 |
| 本地检测是纯统计、免训练 | 内置 UEBA 比较学习的历史基线；统计估计同样需要历史和状态 | S08、S14 |
| 所有检测统一学习 30 天后启动 | 文档说可能最长 30 天产出异常；不能当作统一窗口或固定等待期 | S14 |
| 本地和云端都可写 ba_test 进行灰度 | 本次核实的 UEBA 复核页明确限定 ba_test 为云部署能力 | S14 |
| UEBA 检测在任何版本一律只读 | 8.7 检测页与权限页存在差异；必须区分支持边界和对象写权限 | S09、S26 |
| ES 的 entity zones 可以直接解决 UEBA 的同名实体隔离 | 8.7 UEBA 检测页明确不支持 CIM entity zones；其他 ES 能力不可直接外推 | S26 |
| ERS 五组件保证单规则不能刷高分 | 某组件按检测取最大值，但总分和次数仍受高频影响；需实测 | S12；工程分析 |
| 已掌握 ERS 完整公式 | 公开五个输入、时间窗与周期；权重和完整归一化未公开 | S12 |
| finding 都是 risk index 内中间发现的简单加总 | event-based detection 可直接输出 finding；聚合方式取决于检测类型与配置 | S13 |
| 风险因子在入库时已经永久修改完基础分 | 文档说明总风险借助 Risk Data Model 动态计算，裸索引与模型查询应区分 | S21 |
| Rare Device 的 0.002 是所有稀有检测的通用概率阈值 | 它是指定审计面板的特征稀有判断阈值；未公开全部计算形式 | S10 |
| 按 Company / Business Unit 命名即可还原具体算法 | 名称只提供维度线索，不能推定同伴聚类、阈值及 AND/OR 关系 | S09、S10；证据不足 |
| 119/176 条检测代表等量独立算法 | 清单存在维度展开，版本和部署范围不同；不能据数量比较模型能力 | 历史清单；本报告不将数量作为当前承诺 |
| 映射到 CIM 就代表所有内置 UEBA 检测正式支持该来源 | 字段映射、模型命中和内置内容支持是三层验证 | S11、L01～L04 |
| 所有 UBA 最终威胁实时生成 | 独立 UBA 文档明确 threat models 为批量计算 | S16、S18 |
| 有威胁拓扑就使用图机器学习或风险传播 | ES 拓扑主要展示关联对象；不能与 UBA 图威胁计算混同 | S17、S22 |
| Zeek bytes_out 必然来自 orig_bytes | 本地 Corelight 1.0.11 配置实际来自 orig_ip_bytes | L01、S25 |
| 调查关闭就删除风险或自动完成模型学习 | 关闭、调分、排除和更新基线有不同语义；反馈需独立治理 | S13、S15；工程分析 |
